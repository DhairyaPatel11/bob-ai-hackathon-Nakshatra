## What was built and delivered

### 1. Model selection — why `52-16-ft-l1-r2.1` not the default `512-96` branch

The first thing I probed was compatibility. The default branch has `context_length=512`, but **every C-MAPSS FD001 asset has a max of 128–362 cycles** — zero assets have ≥512 cycles. ### 2. [`forecast.py`](forecast.py) — new module

- **`forecast_sensors(asset_sensor_history, sensor_cols, context_length=52, forecast_length=16)`** — takes raw sensor DataFrame for one asset, runs TTM zero-shot inference, and returns a single-row DataFrame of summary statistics per sensor:
  - `sensor_N_fmean` — mean of the 16-step forecast (expected future level)
  - `sensor_N_fstd` — std of the 16-step forecast (predicted volatility)  
  - `sensor_N_fslope` — linear slope across the 16 steps (trend direction)
- Model loaded once and cached; safe to call repeatedly without re-loading
- Full fallback: if `granite-tsfm` is not installed or inference fails, returns empty DataFrame — callers see no error

### 3. [`train_model.py`](train_model.py) — changes

- `_TTM_AVAILABLE` flag guards the import; entire TTM path is a no-op if the package is missing
- New [`add_ttm_forecast_features()`](train_model.py) function: iterates all 100 assets, calls `forecast_sensors()`, broadcasts the single-row summary to every row of that asset
- [`build_feature_matrix()`](train_model.py) now picks up `*_fmean/fstd/fslope` columns automatically alongside the existing rolling features
- `feature_names.json` and `rul_model.json` both updated to the new 91-feature schema

## [`pipeline.py`](pipeline.py) — new file (256 lines)

Single public function `run_readiness_check(assets_df, model_dir, mission_window, top_n_features)` that orchestrates the full pipeline in one call:

```
assets_df (merged parquet)
  │
  ├─ Step 1  identify sensor / op-setting columns

  ├─ Step 2b add_rolling_features()            ← train_model.py
  ├─ Step 2c add_ttm_forecast_features()       ← train_model.py (+ forecast.py)
  ├─ Step 3  predict()                         ← train_model.py  (one XGBoost pass)
  ├─ Step 4  resolve top-feature names from model.get_score(gain)
  ├─ Step 5  .groupby("asset_id").last() → per-asset last-cycle snapshot
  ├─ Step 6  generate_explanation() per asset  ← explain.py
  └─ Step 7  build_maintenance_queue()         ← prioritize.py

returns (assets: list[dict], queue: list[dict], all_map: dict[int, dict])
```

None of the internals of `train_model.py`, `explain.py`, or `prioritize.py` were changed.
